# Read scripts/lib/journey-quarantine.sh's header before editing this file —
# it documents the format, the fail-safe direction, and exactly what changes
# (and what does NOT change) for a class listed here.

# One row per quarantined TEST METHOD, TAB-separated:
#   <FQCN#method><TAB><issue><TAB><added YYYY-MM-DD><TAB><expires YYYY-MM-DD><TAB><reason>
#
# A row is a REGISTRY entry, not a runtime exclusion. The quarantine itself is
# the `@Ignore("quarantined: #<issue>, expires <date> — <reason>")` annotation on
# the method; this file is what gives that annotation an owner and a deadline.
# The guard reconciles the two in BOTH directions, so neither can drift:
# a row without its @Ignore is a lie, and an @Ignore without a row is a
# graveyard entry.
#
# scripts/check-journey-quarantine-expiry.sh fails CI once `expires` has
# passed. Resolve an entry by DELETING its row (the class is fixed or removed)
# or by RE-TRIAGING it (replace the row with a fresh `added`/`expires` and a
# reason that says why it is still flaking) — never let a row sit expired.

# expired.
